# Deliverable spec — software project

> Inlined into every `software_project` post-gate worker task. All artifacts must
> be written to the shared persistent workspace for the item.

## Required delivery record

Create or update `DELIVERY.md` with:

1. **Objective and approved scope** — what was requested, included, and excluded.
2. **Architecture decisions** — the selected approach, key trade-offs, and any
   assumptions.
3. **Implementation inventory** — files/artifacts created or changed and their
   purpose.
4. **Run instructions** — exact local setup and execution steps for the persistent
   workspace.
5. **Testing** — test plan, commands actually run, and their actual results. State
   clearly when testing was not possible.
6. **Review** — findings, fixes made, and issues explicitly deferred.
7. **Documentation and handoff** — user/developer guidance, known limitations,
   risks, and recommended next actions.

## Quality bar

- Do not claim a test, integration, deployment, or review passed unless it was
  actually performed.
- Keep project scope and external side effects within the approved proposal and
  scope rails.
- Cite externally researched technical claims in the delivery record.
