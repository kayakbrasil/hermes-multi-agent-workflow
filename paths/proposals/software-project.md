# Software project proposal template

> The orchestrator completes this concise approval packet from the intake,
> research, and architecture stages. It must be sufficient for a human to approve,
> modify, or shelve the proposal without relying on hidden context.

```
SOFTWARE PROJECT proposal: <title>   (slug: <slug>)

Project
- Classification: <website | web_app | mobile_app | automation>
- Objective: <desired outcome>
- Intended users: <who benefits>
- Constraints: <known constraints>

Prioritization
- Score: <total>/100 (<short breakdown>)
- Why now: <personal value, reuse, learning, or other rationale>

Research and architecture
- Key findings: <bullets>
- Recommended approach: <one concise paragraph>
- Scope included: <bullets>
- Scope excluded: <bullets>

Delivery
- Planned artifacts: <code, tests, documentation, delivery record>
- Workspace: <pipeline-managed persistent workspace>

Decision signals
- Complexity: <low | medium | high>
- Implementation effort: <small | medium | large>
- Expected external costs: <none | low | medium | high>
- Confidence: <low | medium | high>
- Major uncertainties: <bullets or none known>

Reply: approve <slug> | shelve <slug>: <reason> | modify <slug>: <change>
```
